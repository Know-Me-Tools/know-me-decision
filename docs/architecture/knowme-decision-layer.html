KnowMe Decision Layer

Julia 1 is the planned built-in default: Rust APIs, embedded native ONNX Runtime and all model assets installed before first launch. Desktop and mobile run supported decisions offline without a key, configuration file or model server. Optional hosted Jev uses a TypeSafe key plus trusted host permission; adding a key leaves the local default unchanged. One decision proxy provides native, Jev-compatible and MCP interfaces. Larger models and browser execution remain optional extensions.

01 · Context

Where this came from

In the 27 September mentoring session with Treston (46:55–49:11), Travis described a decision model sitting between a patient and a counselor's digital twin. The model routes each message to the right agent, then decides whether the twin's draft answer can go out or should be handed to the human counselor, with a summary and a pointer. He expected about 90% of questions to be handled without the counselor, all logged for the counselor's next session.

The model he named was TypeSafe AI's Jev, a "System One" model. It fills a typed schema in one non-autoregressive pass and attaches a calibrated probability to each answer. Its three primitives are Choice (up to 255 options), Score (an ordinal rubric) and Noul (the probability that a statement is true). Jev is hosted-only, with no weights, no on-prem option and no published BAA. That rules it out for an architecture where PHI and counseling data stay on the user's devices.

This report covers four things:

  • the self-hostable alternatives (from the research run)
  • how to package them as a Rust crate library and MCP server that fits the existing codebases (from reading the four repos)
  • concrete decision use cases for CounselMe and the Prior Authorization Workbench
  • a set of AgentSkills-compatible decision skills, distributed through a plugin marketplace

Honesty about the numbers. Nearly every benchmark for the open Jev-style models is self-reported. The models are days or weeks old and were measured against Jev reference values, not in a head-to-head run. Treat them as a shortlist to evaluate on your own data, not as settled rankings.

03 · Research

Technique layer

Four techniques turn any open LLM into a decision model. They are what decide-llm and decide-calibrate implement.

One-pass option scoring

Prefill the state once, then read the next-token logits restricted to the option tokens. For several questions over one state, fork the cache for each question. On Qwen3.8's hybrid Gated DeltaNet layers, paged-attention KV reuse doesn't cover the linear-attention state, so the candle-vllm fork needs a state snapshot and fork primitive.

Constrained decoding

Use it for the fields you actually generate: action items, missing-evidence lists, criteria decomposition. llguidance is a Rust crate that computes token masks at about 40–50 µs per token, so it fits directly in the candle-vllm fork. It guarantees the output structure, but says nothing about calibration.

Calibration

Temperature scaling fixes average overconfidence (Laya's ECE went from 0.466 to 0.081). For escalation, crisis and void classes, use class-conditional (Mondrian) split conformal to target class-conditional coverage under documented sampling assumptions. Minimum sample counts do not prove deployment recall or automated-action safety. Evaluate the routed system and each population; pooled fallback cannot claim subgroup coverage.

Fine-tune on your decisions

Options range from SetFit (dozens of labels, CPU) to a full ModernBERT fine-tune to LoRA plus a head on Qwen (Kev's recipe; soft targets beat hard labels). Capture overrides and representative human-reviewed samples from all outcomes. Separate training, calibration and test sets; synthetic cases never count toward calibration-positive minimums.

One workspace, knowme-decide, with a no-I/O core and feature-gated backends. The same library runs in-process in three products and behind an MCP server in the fourth.

The host contract everyone shares

The normative proposed types are in PLAYBOOK §5. Choice returns a selected option and distribution; Score returns a level distribution and expected value; each Noul returns its own P(true) and true/false prediction set. Batches retain per-question outcomes. These are planned contracts, not an available Rust API.

Authenticated host policy and trusted data provenance authorize destinations.
Tripwires run first. A sensitivity model can only remove destinations.
An eligible backend proposes an answer; every required guard runs.
The pure policy returns a proposal and redacted audit record.
The trusted host persists the audit record before releasing Act.
Audit failure withholds Act and reports an explicit failure without a fabricated audit ID.
Urgent Escalate remains deliverable with an explicit audit-failure status.
Clinical state changes require a separate human-confirmed host command.

One Axum server exposes TypeSafe's Jev API, a native API and MCP. The default route is bundled Julia ONNX. Optional learned routing ranks configured Jev, Qwen, Laya and other compatible deployments: trusted host policy sets permitted destinations and a sensitivity gate may only narrow them.

Built in on desktop and mobile

Installed before first launch

The planned julia-onnx bundle includes the verified Julia 1 graph and weights, tokenizer, native ONNX Runtime, manifest and default settings. Windows, macOS and Linux can use a linked library or bundled sidecar; Android and iOS use an in-process host library/FFI. No Python worker, first-run download or user-run model server. Rust owns the API; ONNX Runtime adds native C/C++ dependencies. The core remains free of I/O.

Jev is optional

A TypeSafe key enables provider availability, not permission to send data. Local remains the default until explicit selection or an authorized routing policy permits Jev. PHI, unknown provenance and DeviceOnly never reach hosted providers. Missing or invalid keys cannot prevent local startup. Sidecars use JEV_API_KEY; mobile credentials stay in the host secure store, outside remote-free decide-lite.

Useful answers with explicit limits

Julia supports 2–20 candidates per call, fractional ordinal Score and independent Noul. The framework limit of 255 does not extend Julia. Unsupported counts and overlength input produce conservative outcomes or explicit refusal, without silent truncation, splitting or remote fallback. Missing valid calibration or a required guard means Review or Escalate. No starter calibration evidence is invented.

The cost of zero setup

The 144.3M-parameter FP32 weights alone are about 550.5 MiB, plus tokenizer and runtime memory. Quantization is unproven for this release. The 8,192-token runtime capacity has smoke-test evidence; earlier accuracy evaluation used 1,024 tokens. Published Android Python-driven measurements do not certify a native app or iOS. Exclude the reported faulty XNNPACK path until parity passes.

Release gate: M0 Spike F proves native feasibility; M1a exercises Julia plus explicitly permitted Jev; M4 proves fresh-install offline operation, primitive/logit parity, cold/warm latency, peak memory, package size, resource failures and host audit/egress behavior on all five native platforms. This is a selected plan, not shipped support. Browser/WebGPU has a separate acceptance profile.

05 · Build NEW

The decision cascade

Tripwires can exit straight to escalation. A calibrated encoder may skip the LLM head, but never a required guard. A guard veto survives later calibration. The host commits the audit record before releasing Act; failures are explicit.

UAR · native crate

  • Intent routing: add ClassifierBackend::Decision implementing IntentClassifier (src/uar/runtime/matching/intent/mod.rs). Its calibrated prediction set replaces the should_accept top-1 plus margin heuristic and the out_of_scope < 0.1 rule.

  • Config and features: a new decision_models: section. The decide feature goes into desktop-full and server-full, and decide-lite (tripwire, encoder, calibrate) into embedded-mobile. Emit events through RuntimeEventSink.

KnowMe · on-device L2 crate

  • New crate: gen_ui_decide at L2, behind a DecisionProvider trait in gen_ui_types, mirroring InferenceProvider.
  • Where it runs: desktop links it in-process through tauri-plugin-gen-ui, and mobile through gen_ui_ffi (flutter_rust_bridge). Android and iOS use the embedded native ONNX baseline, subject to real-device acceptance. No mobile inference subprocess is required.
  • Agent tools: register native tools in gen_ui_agent/src/uar.rs. Surface decisions through the existing agui.guardrail and uar.guardrail.flagged events, which the UI already understands.
  • Locality: each spec declares its locality, and decide-policy enforces the model-configuration rule that resolution never escalates locality without a Cedar grant or a user prompt.
  • First outbound MCP server: decide-mcp can be KnowMe's first outbound MCP server, the one docs/strategies/skill-support/README.md §3 designs but hasn't built.
  • Data sources: the P2P layer (knowme_ofp) and the SurrealDB graph (gen_ui_db_graph) hold the state the decisions read. Omi, Oura and FHIR ingestion don't exist in the repo yet, so CounselMe signal decisions depend on those connectors.

Prior-Auth Workbench · pure kernel

  • New crate: aso-decide sits beside clinical-docs with no I/O, and aso-host reaches it through a port. It follows "agent kernels do not write" and "proposes; never writes".
  • Outputs map to existing states: met, gap or void (never two states). Abstaining maps to the existing classification_needs_review fixture path. Proposals are persisted only through the evidence and reassessment commands after a coordinator or surgeon confirms.
  • Agent slots it fills: 04 Criteria Matcher, 06 Gap Analyst, 12 Response Parser, 13 Denial Classifier and 18 Gold Card Tracker. None has been built yet.
  • Calibration data: ground truth is criterion_observations and determinations. The Wilson-bound shared_criterion_summaries is the only statistical precedent in the codebase.
  • MCP: read-only tools join aso-document-assembly/src/mcp.rs, or the sidecar is allowlisted in generation_mcp.rs. There are no affirm, sign or submit tools, ever.
  • Why it matters: production PHI inference is disabled today until a US provider signs a BAA. On-prem decide-llm removes that blocker for decisions.

# Escalation gate

## Steps
1. Call `tripwire_scan` with pack `counselme-crisis` on the patient message AND the draft.
   Any hit → stop. Outcome is `crisis_protocol`. Do not call other tools.
2. Call `sufficiency_check` with the question, the draft and the knowledge refs.
3. Call `decide_choice` with spec `counselme.sufficiency.v3`, passing step 2 scores as state.
4. Follow the returned `outcome`, never the top `value`:
   - `act` → send the draft.
   - `review` → do not send. Post summary + pointer to the counselor; tell the patient
     when to expect a reply (see references/OUTCOMES.md for wording).
   - `escalate` → crisis protocol: 988 and the counselor's safety plan.
5. Record `audit_id` with the conversation turn.

## Never
- Never lower a recall floor or skip a step to raise the automation rate.
- Never rewrite the draft to get it past the gate; hold it instead.
- In restricted jurisdictions (see CM-04), treat any therapeutic content as `review`.

13 · Decide

Safety & regulation

Illinois HB 1806 CounselMe

Public Act 104-0054, effective 4 August 2025, bars AI from independent therapeutic decisions and from therapeutic communication with clients, with penalties of up to $10,000 per violation. The escalation gate doesn't cure this. Geofence Illinois, or limit the product there to supplementary support with consent (CM-04). Get counsel's opinion, and track similar laws in other states.

FDA CDS guidance, Jan 2026 both

Non-device CDS supports a clinician "without replacing or directing" their judgment. Matching records to guidelines is a recognized pattern, and interpreting repeated physiologic measurements is likely a device function. Prior-auth stays transparent and proposal-only. CounselMe wellness signals stay wellness-framed (CM-08).

MedGemma license prior-auth

The HAI-DEF Prohibited Use Policy bans automated decisions in healthcare and insurance. MedGemma is allowed as an extractor whose output a person reviews, and never as the model that decides met/gap/void.

Hosted routing both

No applicable BAA is established by this plan. PHI and unknown data remain excluded from hosted adapters. Explicit trusted grants authorize non-PHI destinations; a classifier only vetoes. Alibaba Token Plan and Coding Plan prohibit custom application backend use, so a permitted API service or explicit provider authorization is required. Provider region labels do not prove inference residency.

HIPAA, BAA and Texas prior-auth

Production PHI inference is disabled in the workbench today until there is a BAA provider. Self-hosting removes that dependency for decisions. The spec already tracks Texas SB 1188 and TRAIGA AI-disclosure reporting, so each decision's audit_id should feed those reports.

Not legal advice. The Illinois statute, the FDA's device boundary and the MedGemma license each need counsel's reading for the specific product and jurisdictions.

15 · Notes

Caveats & sources

  • Nearly every figure for the Jev-style open models is self-reported, days old, and measured against Jev reference values rather than a new head-to-head run. MedGemma 27B hardware needs are estimates. Guard-model leads come from the vendors.
  • Crisis-detection performance depends on fine-tuning and data, not on which model you pick. No model detects suicide risk until it has been validated on your population with clinician-labeled data.
  • The repo findings reflect a read of each codebase on 27 September 2026. The crate names, tool names and spec IDs in this report are proposals and don't exist yet.
  • The example numbers in the semantic result and sequence diagram are illustrative. The published IPFS snapshot predates this local built-in-default update; it has not been republished. Publication of this architecture document does not establish runtime validation; implementation and acceptance gates remain pending.
